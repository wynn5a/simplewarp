## Responsibility

Typed settings: setting definitions, loading and live updates (`settings`), and the value types
plus derive support (`settings_value`, `settings_value_derive`). The documented settings schema is
generated by an app-side bin (`generate_settings_schema`).

## Boundary

No UI — the settings pages are `settings_view` in the app. Persisted setting keys are part of the
compatibility contract: keys are stable or tombstoned, never reused (principle in the
[goal doc](../../../specs/SPEC.md)).
