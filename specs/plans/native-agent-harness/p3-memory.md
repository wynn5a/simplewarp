# P3 规格：Memory

上级计划：`specs/plans/native-agent-harness.md` 的 "P3 Memory"，决策 D3（已批准：agent 写入的 memory
默认要用户批准，设置里可以改成自动批准）。本文是 P3 的实现规格，评审按本文逐条核对实现。L2（跨会话
检索 `search_conversations`）不在本阶段。

## 目标

1. L0 上下文文件：项目里的 `CLAUDE.md` 和 `AGENTS.md`/`WARP.md` 一样作为项目规则注入；同一目录只注入
   一个文件。`~/.agents/APPEND_SYSTEM.md` 存在时追加到 system prompt 末尾。
2. L1 agent 写入的 memory：模型可以调用 `remember { content, scope }`，经用户批准（或设置为自动批准）后
   写成一条 Knowledge 规则（`AIFact::Memory`），之后的请求都能在 system prompt 里看到它；`project` 作用域
   只对写入时所在的 repo 生效。
3. Knowledge 页能看出哪些条目是 agent 添加的、属于哪个项目，并能像普通规则一样编辑、删除。

## 范围

- `crates/repo_metadata`：standing query 的规则文件名加 `CLAUDE.md`。
- `crates/ai`：`ProjectRules` 的同目录优先级加入 `CLAUDE.md`。
- `crates/local_inference`：读 `~/.agents/APPEND_SYSTEM.md` 追加到 system prompt；`remember` 工具的
  schema、参数转换、结果渲染；system prompt 里关于 memory 的说明。
- `crates/warp_multi_agent_api/proto`：`ToolCall.Remember`、`RememberResult`、`ToolType.REMEMBER`
  （只做加法）。
- `crates/cloud_object_models`：`AIMemory` 加 `root_path`、`source`（serde 缺省，只做加法）。
- `crates/ai`：`AIAgentActionType::Remember`、`AIAgentActionResultType::Remember` 及转换。
- `app/src/ai`：请求里带上 memory（全局 + 当前 repo）、执行器 `execute/remember.rs`、权限
  `BlocklistAIPermissions::can_write_memory`、AI block 里的确认/结果视图、Knowledge 页标注、设置项和
  Command Palette 条目。

## 非范围

- L2 跨会话检索。
- 不读 `~/.claude/CLAUDE.md`（理由见设计 §2）；不读 `CLAUDE.local.md`、`.claude/CLAUDE.md`。
- 不提供"完全替换 system prompt"的文件。
- 执行配置（profile）不加 memory 写入的权限项（理由见设计 §6）。
- 不做 memory 的自动整理、过期、去重合并；不做向量检索。
- `/init` 的"已初始化"判断（`init_project/model.rs:443` 只认 `AGENTS.md`/`WARP.md`）不变：`CLAUDE.md`
  仍是 `/init` 可以链接过来的格式（`init_project/mod.rs:42`）。

## 设计

### 1. 项目上下文文件：`CLAUDE.md`

- `standing_queries.rs` 的规则文件名改为 `["WARP.md", "AGENTS.md", "CLAUDE.md"]`。
- `RuleAtPath` 加 `claude_md` 一格；`respected_rule` 为 `warp_md.or(agents_md).or(claude_md)`；
  `rule_paths`/`retain_rule_paths`/`upsert_rule` 同步。文件名到格子的映射抽成一个函数
  `RuleFileKind::from_file_name`（小写比较），三个文件之外返回 `None`。

**优先级（完整定义）：**

- 同一目录：`WARP.md` > `AGENTS.md` > `CLAUDE.md`，只注入排第一的那一个；其余两个不注入、也不列在
  "More rule files exist"。`CLAUDE.md` 是 `AGENTS.md` 的软链接（`/init` 的链接方式）时，两者在同一目录，
  只注入 `AGENTS.md`，内容不会出现两遍。
- 不同目录：各目录独立按上一条选出一个；当前目录及其祖先目录（到项目根为止）的规则都是 active，其他
  目录的规则作为 "More rule files exist" 列出（行为不变）。
- 全局与项目：全局规则文件（`~/.agents/AGENTS.md`）与项目规则并列注入，在前；Knowledge 规则和 agent
  memory 在后（设计 §4）。没有覆盖关系，冲突由模型按 "越具体越优先" 处理（不变）。

### 2. 全局文件：不读 `~/.claude/CLAUDE.md`

`~/.claude/CLAUDE.md` 是 Claude Code 的用户级 memory：内容通常针对 Claude Code 写成（工具名、hook、
slash command），对 SimpleWarp 的工具集是错误指令；它还可能含有用户只想给 Anthropic 一家看的内容，而
SimpleWarp 会把它发给用户配置的任意 provider（OpenAI、自定义端点）。一个新装的终端悄悄读别的工具的私有
配置并外发，既意外又有隐私风险。需要共用的用户可以显式做软链接
`ln -s ~/.claude/CLAUDE.md ~/.agents/AGENTS.md`，这一行写进 `app/src/ai/SPEC.md`。

### 3. `~/.agents/APPEND_SYSTEM.md`

- 由 `local_inference` 在每次非摘要请求时读取（`prompt::read_appended_system()`）：先看文件大小，超过
  256 KB 不读（`log::debug!` 记字节数）；不存在、读失败或空白视为无，NotFound 以外的读错误以
  `log::debug!` 记错误类型（不记内容、不记路径）。
  追加到 system prompt 的**最末尾**（固定文本、环境、MCP 段之后），前面空一行，不加标题（用户自己控制
  措辞），超过 60,000 字符时截断（同规则文件的 `MAX_ITEM_CHARS`）。摘要请求不追加（摘要 prompt 有固定
  格式要求）。
- **为什么在 `local_inference` 读而不是由 app 维护缓存。** 请求 proto 没有承载它的字段，加字段只为了
  传一段本机文件不值得；全局规则的 watcher 以目录去重（`global_rules.rs:183`），给同一个 `~/.agents`
  再挂一个源要改造 watcher。每个请求读一个小文件的代价可以忽略，而且总是最新。
- **缓存稳定性。** 位置固定在末尾，内容只在用户改文件时变；一次读失败（文件被编辑器原子替换的瞬间）
  会让那一个请求的 system prompt 少一段，代价是一次缓存未命中，不影响正确性。
- `Prompt::for_request` 保持纯函数，新增 `Prompt::with_appended_system(Option<&str>)`，由
  `stream.rs` 读文件后调用，测试不依赖 home 目录。

### 4. memory 进入请求

`app/src/ai/agent_memory.rs`（新模块）：

```rust
/// Knowledge rules and agent memories for one request, in a stable order.
pub struct RequestMemories {
    pub global: Vec<(String, String)>,
    pub project: Option<ProjectMemories>,
}
pub struct ProjectMemories { pub root_path: String, pub rules: Vec<(String, String)> }

/// 纯函数：从全部事实里选出全局的（root_path 为空）和属于 `project_root` 的。
pub fn select_memories<'a>(memories: impl IntoIterator<Item = &'a AIMemory>,
    project_root: Option<&str>) -> RequestMemories;
/// 纯函数：同一作用域里是否已有 trim 后内容相同的条目（执行器去重用）。
pub fn contains_memory<'a>(memories: impl IntoIterator<Item = &'a AIMemory>, content: &str,
    root_path: Option<&str>) -> bool;
/// 全部未删除的 Knowledge 规则。
pub fn saved_memories(app: &AppContext) -> impl Iterator<Item = &AIMemory>;
/// cwd 所在 repo 的根（`DetectedRepositories::get_root_for_path`），显示路径形式。
pub fn project_root_for(cwd: &str, app: &AppContext) -> Option<String>;
```

- 标题：有 `name` 用 `name`；agent 写入且无名的用 `"Agent memory"`；用户写入且无名的用 `"Rule"`
  （与现在 `add_global_rules` 的缺省一致）。每组按 `(标题, 内容)` 排序，保证同一组事实产生同样的 prompt。
- `RequestParams.global_rules` 换成 `memories: RequestMemories`；`add_global_rules` 改为
  `add_memories`：全局组照旧作为空根条目追加；项目组若请求里已有同根的 `ProjectRules` 条目（项目规则
  文件）就并入它的 `active_rule_files` 末尾，否则追加一个新条目。于是它们都在 system prompt 的
  "# User rules" / "# Project rules" 段里，属于稳定前缀。
- 属于别的 repo 的项目 memory 不进请求。`project_root_for` 在主线程上执行，`get_root_for_path` 会
  canonicalize cwd（一次文件系统调用，`block.rs:3560` 也这样用）。
- 远端会话（`SessionType::WarpifiedRemote`）的 cwd 是另一台机器上的路径，`project_root_for` 对它返回
  `None`：既不绑定、也不注入本机任何 repo 的项目 memory（全局 memory 照常注入）。
- **缓存稳定性。** memory 只在写入、编辑、删除时变；一次 `remember` 成功后下一个请求的 system prompt
  变化一次（缓存未命中一次），这是让模型立刻看到新 memory 并据此去重的代价，可以接受。
- `memory_enabled` 已经缺省开启，本阶段不改它的缺省值；它关闭时 memory（无论来源）都不进请求，
  `remember` 工具也不提供（模型写了也看不到，没有意义）。

### 5. `remember` 工具

**proto（只做加法，登记在 `crates/warp_multi_agent_api/SPEC.md`）：**

```proto
// task.proto, Message.ToolCall
Remember remember = 39;
message Remember {
  string content = 1 [ (sensitive) = true ];
  Scope scope = 2;
  enum Scope { GLOBAL = 0; PROJECT = 1; }
}
// task.proto 顶层
message RememberResult {
  oneof result { Success success = 1; Error error = 2; }
  // project_root: 绑定的项目根，空 = 全局；already_saved: 已有一模一样的条目，没有再写。
  message Success { string project_root = 1 [ (sensitive) = true ]; bool already_saved = 2; }
  message Error { string message = 1 [ (sensitive) = true ]; }
}
// Message.ToolCallResult.result: RememberResult remember = 43;
// Request.Input.ToolCallResult.result: RememberResult remember = 38;  (request.proto)
// ToolType: REMEMBER = 36;
```

字段号取各自 oneof / enum 当前最大值 + 1，未与 `reserved` 冲突（实现时逐个核对）。

**`local_inference`：**

- `SUPPORTED` 加 `Remember`，wire 名 `remember`。schema：`content`（string，必填）、`scope`
  （enum `["global", "project"]`，必填）。描述："Save one short, durable fact for future conversations…"。
- `to_proto`：`scope` 缺省或无法识别时取 `PROJECT`：映射成 `GLOBAL` 会把一条可能只对当前 repo 成立的事
  扩大到所有项目，`PROJECT` 误写的影响只限于当前 repo。schema 把 `scope` 设为必填，正常模型不会缺省。
- 回放 `tool_use_from_proto` 还原 `{content, scope}`；`render_result`：成功
  "Saved to memory for all projects." / "Saved to memory for the project at `<root>`."，
  `already_saved` 时 "This is already in memory; nothing was saved."；错误为错误文本、`is_error`；
  `stored_result`/`fit_payload` 原样（内容很短）。
- system prompt 增加一节 `# Memory`，紧跟固定文本、在环境段之前（只在请求提供 `remember` 时出现：
  `tools::offers(Remember, supported_tools)`，与工具 schema 的判定相同，空列表表示全部工具；没开 memory
  时 prompt 不变）：
  - 何时记：用户明确表达的稳定偏好、项目约定（构建/测试命令、代码风格、目录约定）、反复踩过的坑及解法。
  - 何时不记：一次性的任务状态和进度、可以从代码里直接读到的东西、秘密（密码、token、密钥、私人数据）、
    用户没有认可的推测。
  - 每条一个事实、一两句话；`project` 用于只对当前 repo 成立的事，`global` 用于用户的通用偏好。
  - 先看 system prompt 里已有的 "User rules"/"Project rules"（含 "Agent memory"），已有的不要再记；
    用户要求"记住"时才主动记，或者在发现值得记的事时简短征求同意后再记。
  - 用户会被请求批准；被拒绝时不要重试同一条。

**app：**

- `AIAgentActionType::Remember { content: String, scope: MemoryScope }`，`MemoryScope { Global, Project }`
  定义在 `crates/ai/src/agent/action/mod.rs`；`AIAgentActionResultType::Remember(RememberResult)`，
  `RememberResult { Saved { project_root: Option<String>, already_saved: bool }, Error(String),
  Cancelled }`；`Cancelled` 不发给模型（与其他工具一致，取消由 `Cancel` 结果表示）。
- `get_supported_tools` 在 `params.is_memory_enabled` 时加 `ToolType::Remember`（本地和远端会话都可以，
  写入的是本机的 Knowledge）。
- 执行器 `RememberExecutor`（`execute/remember.rs`），同步执行：
  0. `!is_memory_enabled()` → `Error("Memory is turned off.")`：这时工具不提供，调用只可能是过期或模型
     编造的，不能写入。
  1. `content.trim()` 为空 → `Error("The memory is empty.")`；超过 2,000 字符 →
     `Error("A memory must be one short fact (at most 2000 characters).")`。
  2. `Project` 作用域：远端会话 → `Error("This session runs on another machine, so there is no local
     project to remember this for. Use scope \"global\" …")`；否则 `project_root_for(cwd)`，cwd 不在
     任何 repo 里 →
     `Error("The current directory is not inside a repository, so there is no project to remember this for. Use scope \"global\" if it applies to all projects.")`。
  3. 已有未删除的事实与之 `trim` 后内容相同且根相同 → `Saved { already_saved: true }`，不写。
  4. 否则 `UpdateManager::create_ai_fact(AIFact::Memory(AIMemory { name: None, content,
     root_path, source: Agent, .. }), …, personal_drive())`，返回 `Saved`。
  - 日志只记作用域和长度（`log::debug!`），不记内容；`AIAgentActionType::Remember` 的 `Display` 也只输出
    作用域和字符数。
- 权限 `BlocklistAIPermissions::can_write_memory(ctx)`：**只看** `AISettings.agent_memory_auto_approve`。
  会话级 auto-approve（`autoexecute_any_action()`）**不**算数（D3）：memory 会进入以后的每一次请求，
  一次任务的自主授权不能扩展到它。否则请求批准；`is_user_initiated` 的执行（用户点批准）照常执行。
- 批准视图：复用 `RequestedCommandView`，新增 `RequestedActionViewType::Memory`：
  - 等待批准时标题 `OK if I remember this for this project?` / `… for all projects?`，按钮为 "Reject" +
    "Save"（普通按钮，Enter 批准）。**没有**分体按钮里的 "Auto-approve" 项：它会打开会话级 auto-approve，
    而那对 memory 无效；`AcceptAndAutoExecute` 对 memory 视图也只保存、不打开会话 auto-approve；
  - 其他状态的标题 `Remember: <内容首行，截到 80 字符>`，展开后用与 MCP 请求相同的 JSON 树显示
    `{ "scope": …, "content": … }`，便于批准前看全文；
  - 视图放进 `AIBlock.requested_mcp_tools`（改名为 `requested_tool_calls`，因为不再只装 MCP），复用焦点、
    选择、批准的处理。
- 持久化：`PersistedAIAgentActionType` 为 `NotPersisted`（与 `InsertCodeReviewComments` 相同）；会话恢复
  走 `convert_conversation.rs` 从 task 里的 `ToolCall`/`RememberResult` 还原。

### 6. 设置与 Command Palette

- `AISettings.agent_memory_auto_approve: AgentMemoryAutoApprove`，bool，缺省 `false`（"ask"），
  `toml_path = "agents.knowledge.agent_memory_auto_approve"`，GUI。
- 放在 Settings > Agents > Knowledge 页（规则所在页，即任务里说的 "Settings > AI"），在 "Rules" 开关下面：
  开关 "Save agent memories without asking"，说明 "When off, you approve each memory the agent wants to
  save. Memories appear in your rules and can be edited or deleted there."；Rules 关闭时置灰。
- Command Palette：`ToggleSettingActionPair::new("agent memory auto-approve", …,
  flags::AGENT_MEMORY_AUTO_APPROVE_FLAG)`，上下文与 Rules 一样要求 `IS_ANY_AI_ENABLED`；workspace 的
  keymap context 在设置为真时插入该 flag。
- **不加到执行配置。** 执行配置的权限是"这个 agent 在这个工作区能做什么"（命令、文件、MCP），以
  `ActionPermission` 三态存在 sqlite 里的 profile 中，并有配置文件格式和 profile 编辑器；memory 写入改的是
  用户全局的 Knowledge，属于用户对自己数据的偏好，放在全局设置一处即可，避免同一件事两个开关、两个
  真值来源。会话级 auto-approve 不适用于 memory（§5）。

### 7. `AIMemory` 字段与 Knowledge 页

```rust
pub struct AIMemory {
    …
    /// The project root this memory applies to; `None` applies to all projects.
    #[serde(default, skip_serializing_if = "Option::is_none")]
    pub root_path: Option<String>,
    #[serde(default)]
    pub source: AIMemorySource,   // enum { #[default] User, Agent }
}
```

- 旧数据反序列化得到 `None`/`User`，行为不变；`skip_serializing_if` 让全局规则序列化后的 JSON 与以前一致。
  不复用废弃的 `is_autogenerated`：旧 Warp 服务端生成的规则可能把它置为真，复用会把那些规则误标为
  agent 添加。
- `edit_ai_rule` 保留 `root_path`、`source`（用户编辑 agent memory 后仍标为 agent 添加，作用域不变）。
- 规则行在内容下面加一行灰色元信息：agent 添加的显示 `Added by agent`；有 `root_path` 的显示
  `Project: <路径>`（`display_location_path` 缩写 home）；两者都有时用 ` · ` 连接。搜索也匹配这一行。
- 列表位置：仍在 Global 标签页（那里是全部 Knowledge 规则；Project 标签页只列项目里的规则文件）。

## 兼容性

- **proto**：全部新增，号未复用；旧客户端/旧 task 不会有 `Remember`。
- **`AIMemory`**：两个 serde 缺省字段；旧数据读出为全局、用户添加；全局规则的序列化结果不变。
- **CLAUDE.md**：已经有 `CLAUDE.md` 的 repo 从此多注入一个文件（同目录没有 `WARP.md`/`AGENTS.md` 时）。
  这是计划要的行为；提示词因此变化一次。只有 `CLAUDE.md` 的 repo 里，它常含 Claude Code 专用内容（工具名、
  slash command、hook），会原样注入给 SimpleWarp 的 agent 和用户配置的任意 provider；需要时加一个
  `AGENTS.md`（同目录优先）即可盖住它。
- **降级**：旧版本读到新数据时忽略 `root_path`、`source`，于是项目 memory 在旧版本里被当作全局规则注入
  所有项目；在旧版本里编辑这类规则会丢掉这两个字段（再升级后它就成了用户添加的全局规则）。只影响降级。
- **APPEND_SYSTEM.md**：文件不存在时 prompt 不变。
- **工具列表**：`memory_enabled` 开启（缺省）时多一个 `remember` 工具和 `# Memory` 段，提示词前缀变化一次。
- **设置文件**：一个新键，缺省 `false`。

## 已知限制

- 项目根取自 `DetectedRepositories`：cwd 所在 repo 还没被检测到（刚 `cd` 进去）时 `project` 作用域会
  报错，模型可以改用 `global` 或稍后再试；只认 git repo，没有 git 的目录不能有项目 memory。
- 同一 repo 的不同路径形式（软链接）canonicalize 后一致；repo 被移动后旧的项目 memory 不再生效
  （Knowledge 页仍可见，可手动删除）。
- 去重只比较 trim 后的全文，近似重复靠 prompt 指导模型避免。
- memory 写入后下一个请求缓存未命中一次。
- `remember` 在非交互（autonomous）模式和会话 auto-approve 下仍需要批准，除非开启 memory 自动批准。
- 远端会话不能写项目 memory，也看不到项目 memory（只看到全局的）。

## 手动验证步骤

1. 在一个只有 `CLAUDE.md`（内容 "Always answer in French"）的 repo 里开 agent 会话问一个问题：期望法语回答。
   加一个 `AGENTS.md`（"Always answer in German"）后新开会话：期望德语，`CLAUDE.md` 不再注入
   （`RUST_LOG=local_inference=debug` 看不到它；或问 agent 规则里有什么）。
2. 写 `~/.agents/APPEND_SYSTEM.md`（"End every answer with 🦀"）：下一个请求起生效；删掉后恢复。
3. 对 agent 说"记住：这个 repo 用 `cargo nextest` 跑测试"。期望：AI block 出现
   "OK if I remember this for this project?"，展开可见全文；批准后模型收到 "Saved to memory for the project
   at …"。
4. 新开会话（同一 repo）问"怎么跑测试"：期望回答提到 `cargo nextest`。`cd` 到另一个 repo 新开会话：
   期望看不到这条 memory。
5. Knowledge 页（Rules）：该条显示 "Added by agent · Project: ~/…"；可编辑（标注保留）、删除；删除后新会话
   不再知道它。
6. 拒绝一次 `remember`：模型收到取消，不重试同一条。
7. 在会话里打开 auto-approve（命令自动执行）后让它记一条：期望仍出现确认（"Reject" / "Save"，没有
   "Auto-approve" 项）。然后在 Settings > Agents > Knowledge 打开 "Save agent memories without asking"（或 Command Palette 的
   "Enable agent memory auto-approve"）：再让它记一条全局偏好，期望不再询问，直接保存。
8. 关闭 Rules：请求里没有 `remember` 工具、没有 memory。
9. `RUST_LOG=warp=info,local_inference=info`：日志里没有 memory 内容。
